## Project: SearchBook

- **Cities:** Ranchi, Delhi, Delhi NCR, Gurugram, Noida, Chandigarh

## 12 Golden Rules
1. **NEVER break existing working functionality.** Always test after changes.
2. **No business logic in `app/` folder.** It's routing ONLY.
3. **No business logic in `frontend/`.** Frontend = UI only.
4. **Controller NEVER touches database.** Always go through service → repository.
5. **Validate ALL input with Zod.** Never trust client data.
6. **No `any` type in TypeScript.** Type everything properly.
7. **No `setState` in Flutter.** Use BLoC for state management.
8. **No `useEffect` for data fetching.** Use TanStack Query (`@tanstack/react-query`).
9. **Every component has a single responsibility.** Split if it does more.
10. **Security first, features second.** Never skip validation or auth checks.
11. **Pagination is ALWAYS Server-Side.** Never fetch all records. Always use limit/offset/page in backend.
12. **Strict SEO Compliance.** All public Next.js pages MUST have dynamic metadata, JSON-LD schema markup, and semantic HTML tags.

## Folder Structure — STRICT

## Import Rules
- `app/` → imports from `frontend/`, `backend/` (API routes only)
- `frontend/` → imports from `shared/`, other frontend modules
- `backend/` → imports from `shared/`, other backend modules
- `frontend/` → NEVER imports from `backend/`
- `backend/` → NEVER imports from `frontend/`
- `shared/` → NEVER imports from `frontend/` or `backend/`

## Import Path Aliases
- `@frontend/*` → `./frontend/*`
- `@backend/*` → `./backend/*`
- `@shared/*` → `./shared/*`

## Backend Pattern — Controller → Service → Repository
- **Route** (`app/api/`) → 2-3 lines, maps HTTP method to controller. Apply middleware here.
- **Middleware** (`backend/middleware/`) → Auth, role check, rate limiting. Reusable.
- **Controller** (`*.controller.ts`) → Parse request, validate with Zod, call service, return response.
- **Service** (`*.service.ts`) → ALL business logic. Rules, limits, orchestration. NEVER touches Prisma.
- **Repository** (`*.repository.ts`) → ONLY Prisma queries. NO business logic.
- **Validator** (`*.validator.ts`) → Zod schemas. Export types with `z.infer`.
- **Types** (`*.types.ts`) → TypeScript interfaces not generated by Prisma.

## Frontend Tech Stack
- **Data fetching:** TanStack Query (server state, caching)
- **Client state:** Zustand (with selectors, never full store subscription)
- **Forms:** React Hook Form + Zod resolver
- **UI:** shadcn/ui + Tailwind CSS + Framer Motion + Aceternity UI
- **URL state:** nuqs (type-safe search params)
- **Components:** Server Components by default. `"use client"` only when interactive.

## SEO & Discoverability Standards 🔍
- **Dynamic Metadata:** Every Next.js page MUST export a `generateMetadata()` function.
- **JSON-LD Schema:** Use structured data (`<script type="application/ld+json">`) for all listings, categories, and breadcrumbs so Google indexes prices/ratings directly.
- **Semantic HTML:** Always use proper tags (`<article>`, `<main>`, `<aside>`, `<h1>` to `<h6>`).
- **Canonical URLs:** Ensure all pages have canonical tags to prevent duplicate content issues.
- **Image Optimization:** Always use `next/image` with proper `alt` tags and `blurDataURL`.

## Performance Rules
- No unnecessary re-renders (React.memo, Zustand selectors, BlocBuilder buildWhen)
- No scroll lag (virtualized lists, cached images, pagination 20/page)
- No re-drawing (RepaintBoundary, AutomaticKeepAliveClientMixin)
- Server Components by default (zero JS for static content)
- Dynamic imports for heavy components (maps, charts, modals)
- Skeleton loading states (not spinners)

## API Response Format — ALWAYS
```json
{ "success": true, "data": {}, "meta": { "total": 0, "page": 1, "limit": 20 } }
{ "success": false, "error": { "code": "ERROR_CODE", "message": "..." } }
```

## Database Rules
- Prisma ORM with PostgreSQL
- ALWAYS add `createdAt`, `updatedAt`, `deletedAt` (soft delete)
- ALWAYS add indexes on filtered/sorted columns
- ALWAYS use `select` on relations (never expose full user object)
- Use transactions for multi-table operations
- Prevent N+1: use `include`/`select`, never loop queries
